# ESP32-C3 联网桌宠 v1.0.1

修 v1.0 内存过紧的问题。刷进 v1.0 后空闲堆大约只剩 50 KB，运行中最低到过几百字节，天气 HTTPS 和设置页会失败。行为与 v1.0 / v0.5 相同，默认仍是经典立绘。

- 表情包和经典立绘都改成从 `assets` 分区 `esp_partition_mmap` 直接读，按 16 行一条 LZ4 无损解码，只保留 4 KB 条带缓冲。不再在 RAM 里放整帧（40 KB）、压缩缓冲（16 KB）和 zlib 解压状态（约 11 KB）。
- 静态 data+bss：v0.5 为 89,992 字节，v1.0 为 159,568 字节，v1.0.1 为 94,336 字节。比 v0.5 只多 4,344 字节，比 v1.0 少 65,232 字节。推算可用堆大约从 v1.0 的 83 KB 回到约 148 KB（v0.5 约 152 KB）。
- 经典立绘放进同一个表情包，像素与 v0.5 / v1.0 的 `idle.rgb565` 完全一致（打包时逐字节核对）。包缺失或损坏时，用应用里同样压缩的 14,689 字节兜底图，不依赖 RAM 拷贝。
- 表情仍是八张脸、每张 4 帧。帧间隔从约 0.45 秒放到约 0.9 秒。试过每张脸只留 2 帧，跳跃更明显，所以只放慢、不减帧。
- 表情包格式 3，约 534 KB（33 张：经典 + 32 帧），仍在 `0x190000`。旧的 v1.0 格式 2 包不会被误用，会自动退回经典立绘。
- 应用镜像比 v1.0 小约 25 KB（去掉未压缩的 40,960 字节立绘，换上压缩兜底和约 900 字节的 LZ4 解码）。1.5 MB 槽位还剩约 10%。

v0.5 的行为都保留：平时只显示时间和当前天气；挥一次手播放下压回弹再弹出不超过两行的气泡；第一次之后 1 到 10 秒内再挥一次，气泡里一行大号余额；挥手阈值 20 cm；天气 30 分钟刷新；生日 11-11、小粤，两种形象都可用；椭圆下没有小圆点；DeepSeek 每天最多 4 次、间隔至少 12 小时。设置页和串口 `EXPR 0` / `EXPR 1` 仍可切换。

开机串口：`PET READY v1.0.1`。

用 ESP-IDF 5.4.2 编译。应用镜像 `companion-v1.0.1.bin` 写到 `0x10000`（1,411,552 字节）。分区表与 v1.0 相同，NVS 仍在 `0x9000`。不要整片擦除。

```
python -m esptool --chip esp32c3 -b 460800 --before default_reset --after hard_reset write_flash --flash_mode dio --flash_size 4MB --flash_freq 40m 0x8000 partition-table.bin 0x10000 companion-v1.0.1.bin 0x190000 assets-v1.0.1.bin
```

已经刷过 v1.0 的，分区表不用重刷，但应用和表情包要一起刷（格式不兼容旧包）。引导程序没变的话可以不刷 `0x0` 的 bootloader。

GitHub 上这份发布里的 `.bin` 和预览 PNG 是以 `.b64` 文本存放的（推送接口只能传文本）。解出来再核对校验和：

```
python3 tools/decode_b64_assets.py
```

解出的 `companion-v1.0.1.bin` 和 `assets-v1.0.1.bin` 就是要刷的文件。
