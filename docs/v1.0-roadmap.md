# v1.0 路线图：心情 / 表情版本

> 状态：**已实现**。和初稿不同的地方：八个表情都保留（困和打盹分开），每帧是整屏 RGB565 的 zlib 无损压缩（约 13–16 KB），字库只留简体，默认经典版。镜像在 [`releases/v1.0`](../releases/v1.0)。
> 本文是实现前写的目标。标「**提议**」的部分实现时改过；标「**Tim 要求**」的部分没有改。

---

## 0. 一句话目标

**Tim 要求**：在后台（网页设置页）加一个开关，在两个版本之间切换：

- **表情版（心情版）**：「大肥鱼」的脸会跟着心情变化（开心、困、傲娇、担心……），每一张人物图都要按表情**重新画**；
- **经典版**：就是现在 v0.5 的样子，一张固定立绘，没有表情变化。

开关存在 NVS 里，断电重启后保持。

**提议（Haru）**：

1. 表情图不放进应用分区，单独开一个 **数据分区（assets）** 存图；
2. **先只画 6–8 个表情给 Tim 看，Tim 认可画风后再画全套**。

### 1.2 分区和空间（v0.5 实测）

`firmware/idf/partitions.csv`：

```
nvs,        data, nvs,     0x9000,   0x6000
phy_init,   data, phy,     0xf000,   0x1000
factory,    app,  factory, 0x10000,  0x180000
```

- 应用分区 1.5 MB（0x180000 = 1,572,864 B），v0.5 镜像 1,436,208 B，**只剩约 133 KB（约 8.7%）**。其中两套字库约 0.3 MB，立绘 40 KB。
- 0x190000–0x400000 共 **0x270000 ≈ 2.44 MB 没有分配**，这就是给表情图用的空间。
- 结论：一张全屏立绘 128×160×2 = **40,960 B**，应用分区最多再塞两三张，**表情图必须放进新的数据分区**。

### 1.3 立绘是怎么来的

- 原图 `assets/idle.jpg`（825×1024，白底，蓝发女仆头饰少女，深蓝粗描边）。
- `tools/gen_idf_assets.py` 的 `portrait_bytes()`：`ImageOps.contain` 缩到 128×160 以内 → 贴到白底画布、**下移 10 px** → 把原图头顶两个思考小圆点用白色矩形擦掉（`(27,51,39,61)`、`(32,62,38,67)`）→ **旋转 180°** → 存成**大端 RGB565**，写到 `main/idle.rgb565`（40,960 B），`main/CMakeLists.txt` 用 `EMBED_FILES` 嵌进固件。
- `display.c` 的 `paint_portrait(const Pose *)` 每帧从 `idle_rgb565_start` 取像素填进 40 KB 的帧缓冲 `fb`，按 Pose（宽高百分比）做缩放，这就是「下压回弹」动画。
- 屏幕布局（屏幕坐标，未旋转）：上方约 58 px 是气泡 / 首页卡片区（`BUBBLE_AREA = 58`），人物头顶大约从 y≈55 开始，脸在中间，右下角 `CAKE_X=92, CAKE_Y=138, 30×15` 是生日蛋糕。烟花只画在近白色背景像素上（`background()` 判断 R≥29/G≥58/B≥29），所以看起来在人物身后。

### 1.4 屏幕和交互（Tim 定的，v1.0 不能改）

- **首页（陪伴模式）**：上方浅色圆角卡片，左边粗体大时钟（冒号闪烁），右边程序画的天气图标 + 当前气温，下面日期星期和天气（如「18°C 多云」）。**只显示时间和当前温度天气**；不显示余额、今日区间、明日预报，**不显示生日倒计时**。深蓝小胶囊只在提醒、联网后 30 秒 IP、屏幕留言时出现。
- **挥一次手**：播放 v0.1 的「下压回弹」（10 帧缩放表，两次下压约 0.33 秒，气泡不动），然后人物上方弹出 v0.1 样式椭圆气泡（白底深蓝描边，**只画椭圆，不带小圆点**），显示一句「大肥鱼」的话，**最多两行**，7 秒后回首页。有提醒时挥手是关提醒（「喝了就好」/「去走走吧」）。
- **挥第二次**：距第一次 **超过 1 秒、不超过 10 秒** 再挥 → 查 DeepSeek 余额，气泡先「查余额中」，然后**一行**「余额 ¥22.53」，金额用 25 px 粗体时钟数字，长金额自动缩小（9999.99 也放得下），人物照常显示。不到 1 秒的算同一次（忽略），超过 10 秒算新的一次。
- **挥手检测**（`sonar.c`）：每 60 ms 测距；基准 = 最近 9 次读数中位数；读数与基准相差 **超过 20 cm**（可调 5–200，NVS 键 `sweep`，串口 `SWEEP`，网页「挥手灵敏度」）且**连续 2 次**才算一次；要连续 3 次回到基准附近（差 < 阈值一半）且过 600 ms 才能算下一次；东西停在前面 5 秒成为新基准。
- **天气**：Open-Meteo，联网立刻取，之后**每 30 分钟**刷新，失败 2 分钟后重试。地点用经纬度（南昌新建区 `LOC 28.692445 115.815272 新建区`）。
- **生日模式**：寿星 **小粤**，生日 **11-11**，`BAUTO 1`（当天自动进入，第二天自动回陪伴模式）。上方气泡「祝某某 / 生日快乐」+ 程序画的小蛋糕（三根蜡烛，火苗闪烁）；进入时和每 4 分钟放烟花；挥手吹蜡烛（约 1.2 秒）→ 烟花 → 一句生日祝福（10 句 `BIRTHDAY_WISHES`，洗牌袋），蜡烛 60 秒后重新点亮。生日模式下**不调 API**。串口 `BDAYDEMO` 演示 3 分钟。
  - 注：板上目前存的名字是繁体「小粵」，Tim 要的是「小粤」，可以在网页改，或者 v1.0 刷机后顺手用 `BNAME 小粤` 改（见第 8 节问题）。

### 1.5 句子池和 DeepSeek

- 人设：「大肥鱼」= 中文网友给 DeepSeek 起的外号，拟人形象是蓝发萌系少女，DeepSeek 小粉丝，爱吃白饭，总是困困的（额头推着眼罩），温柔俏皮、有点傲娇，偶尔自称「本鱼」。全文在 `main/prompts.h`（`PET_SYSTEM_PROMPT`、`PET_USER_PROMPT`），`tools/prompts_to_readme.py` 同步到 README。
- 每句带「时段 × 天气类别」桶：时段 `any/morning/noon/afternoon/evening/night/late-night`，类别 `general/rain/hot/cold/clear/weekend`；支持 `{temp}` `{weather}` 占位符。
- 池子：20 句内置种子 + 最多 40 句生成句（`GenLine{tag, shows, used, pad, text[72]}`，`POOL_VERSION = 2`），洗牌袋 + 避开最近 6 句，说满 5 次退休。整个池子是带 CRC32 的 NVS blob（键 `pool`），坏了回落到种子。`POOL SELFTEST` 用临时键 `pooltst` 跑 6 项坏数据测试。
- 补充：未说过的 < 20% 时调一次 `deepseek-flash`（关思考，`json_object`，`max_tokens` 1500）要 20 句，返回 `{"l":[["时段","类别","句子"],...]}`。**每天最多 4 次（`LLM_DAILY_CAP`），两次至少隔 12 小时**，计数和时间存 NVS（`llmn`、`llmd`、`llmt`），重启也算。

### 1.6 NVS（命名空间 `pet`）

| 键 | 类型 | 含义 |
|---|---|---|
| `ssid` `pass` | str | Wi-Fi（**值绝不能进仓库、日志、文档**） |
| `key` | str | DeepSeek 密钥（同上） |
| `city` `lat` `lon` `geofix` | str/int | 天气地点 |
| `tz` | int | 时区 8/9 |
| `drink` `move` `q0` `q1` `rpause` | int | 喝水 / 久坐 / 勿扰 / 暂停 |
| `mode` | int | 0 陪伴 / 1 生日 |
| `bname` `bmon` `bday` `bauto` | str/int | 寿星名字、生日月日、自动切换 |
| `msg` | str | 屏幕留言 |
| `sweep` | str | 挥手阈值（`sonar.c`） |
| `pool` / `pooltst` | blob | 句子池 / 自测临时键 |
| `llmn` `llmd` `llmt` | int/str | 今日 AI 调用次数、日期、上次调用时间 |
| `boots` | int | 开机次数 |

数字用 `load_int(key, 默认, 最小, 最大)` 读，超范围用默认值。键名最长 15 字符。

### 1.7 串口命令（v0.5）

`SSID` `PASS` `KEY` `CITY` `LOC` `DRINK` `MOVE` `QUIET` `PAUSE` `TZ` `MODE PET|BDAY` `BNAME` `BDAY m d|OFF` `BAUTO 0|1` `MSG` `SWEEP n` `SONAR 0|1` `PET` `POOL` `POOL LIST` `POOL REFILL` `POOL SELFTEST` `REBOOT` `WEBTEST` `BDAYDEMO [OFF]` `AP [OFF]` `FETCH` `STATUS` `SCAN` `FORGET`。v1.0 全部保留，只增加。

### 1.8 构建和刷机（v0.5 的方式）

```sh
. $HOME/esp/esp-idf/export.sh          # ESP-IDF 5.4.2
python3 tools/gen_idf_assets.py         # 改了 quotes.h / 立绘 / 字库时
cd firmware/idf && idf.py set-target esp32c3 build

# 刷之前一定先备份整片 4 MB
python3 -m esptool --chip esp32c3 --port /dev/cu.usbmodem1101 read-flash 0x0 0x400000 backup-$(date +%Y%m%d-%H%M).bin
# 只写应用（分区表不变时）
python3 -m esptool --chip esp32c3 --port /dev/cu.usbmodem1101 write-flash --flash-mode dio --flash-size 4MB --flash-freq 40m 0x10000 build/companion.bin
```

**不要直接 `idf.py flash`**（会重写引导程序和分区表）。之前的做法是在别的机器上编译，再在 Tim 的 Mac 上用 esptool 刷。Mac 上不要装大东西。

## 2. v1.0 功能规格

### 2.1 表情列表（**提议**）

第一批（**给 Tim 审的 8 个**，带 ★）+ 第二批（审过以后再画）。`id` 是资源包里的编号，固件里用枚举 `EXPR_*`。

| id | 名字 | 画面要点 | 批次 |
|---:|---|---|---|
| 0 | `neutral` 平常 | 现在 idle 的神态重画：半睁的困困眼、小嘴 | ★ |
| 1 | `happy` 开心 | 眯眼笑（^ ^）、张嘴笑、腮红 | ★ |
| 2 | `sleepy` 困困 | 眼睛只睁一条缝、打哈欠小嘴、头微歪 | ★ |
| 3 | `sleeping` 打盹 | **眼罩拉下来盖住眼睛**、嘴边小泡泡或「z」 | ★ |
| 4 | `tsundere` 傲娇 | 眼睛看向一边、鼓腮 / 嘟嘴、脸红 | ★ |
| 5 | `surprised` 惊讶 | 圆眼睛、小 o 嘴、头顶一个小「!」（不能进气泡区） | ★ |
| 6 | `worried` 担心 / 委屈 | 八字眉、眼角泪光、嘴角向下 | ★ |
| 7 | `excited` 兴奋 / 庆祝 | 星星眼、大笑、两颊亮晶晶（生日用） | ★ |
| 8 | `hungry` 馋白饭 | 流口水、眼睛发亮看前方 | 第二批 |
| 9 | `thinking` 深度思考 | 眼睛向上看、嘴抿着（查余额中用） | 第二批 |
| 10 | `cold` 好冷 | 缩脖子、鼻头红、发抖线 | 第二批 |
| 11 | `hot` 好热 | 汗滴、吐舌头 | 第二批 |

每个表情另画一张 **眨眼帧** `blink`（眼睛闭上，其余完全相同），用于空闲眨眼；`sleeping` 不需要。可选：`blow`（吹蜡烛，嘟嘴吹气）给生日模式用。

> 「每个图都要重新画」：v0.5 只有一张立绘（动画是同一张图缩放），所以 v1.0 的「全部图」= 上表每个表情 1 张 + 眨眼帧 1 张（+ 可选 blow）。12 个表情 × 2 ≈ 24 张 × 40 KB ≈ 0.96 MB，远小于新分区。

### 2.2 心情触发和映射（**提议**）

心情引擎每次 UI 刷新时算出「当前表情」，**优先级从高到低**，第一条命中就用：

| 优先级 | 场景 | 表情 |
|---:|---|---|
| 1 | 生日派对：吹蜡烛动画中 | `blow`（没有就 `excited`） |
| 2 | 生日派对：放烟花 / 显示生日祝福 / 生日模式空闲 | `excited` / `happy` 交替 |
| 3 | 挥手动画（下压回弹那 0.33 秒） | 从 `sleeping` 被叫醒 → `surprised`；否则保持当前表情 |
| 4 | 余额气泡：查询中 | `thinking`（没有就 `neutral`） |
| 5 | 余额气泡：结果 | ≥ ¥20 `happy`；¥5–20 `neutral`；< ¥5 `worried`；失败 / 稍后再试 `tsundere` |
| 6 | 语录气泡（7 秒） | **这句话的心情标签**（见 2.5）；没有标签时按关键词推断 |
| 7 | 喝水 / 久坐提醒胶囊在显示 | `worried`（关心你）；挥手关掉提醒那句用 `happy` |
| 8 | 空闲，深夜 23–4 点且 ≥ 10 分钟没人挥手 | `sleeping` |
| 9 | 空闲，深夜 23–4 点 / 下午 14–16 点 | `sleepy` |
| 10 | 空闲，下雨类别成立 | `worried`（第二批前）/ 之后可做「看雨」 |
| 11 | 空闲，气温 ≥ 30°C / ≤ 10°C | `hot` / `cold`（第二批到位前用 `sleepy` / `neutral`） |
| 12 | 空闲，饭点 11:30–12:30、17:30–18:30 | `hungry`（第二批到位前 `neutral`） |
| 13 | 其他 | `neutral`，每 3–6 秒随机眨一次眼 |

- 某个表情在资源包里不存在 → 用 `neutral`；`neutral` 也没有 → 用固件内置 `idle.rgb565`。
- 空闲表情变化不要太频繁：同一个空闲表情至少保持 60 秒（防抖），气泡结束回首页时按当前条件重新算。
- 经典版下心情引擎**完全不生效**，画面和 v0.5 一模一样。
- 串口 `STATUS` 增加一行：`expr mode=1 now=sleepy reason=late-night-idle pack=ok v20261115 faces=8/12`。

### 2.3 美术要求

**提议**，第一批交给 Tim 审之前按这个画：

- **和现有立绘保持一个人**：参考 `assets/idle.jpg` 和 `firmware/idf/context-preview.png`。蓝色长发、白色女仆荷叶边头饰 + 呆毛、蓝色小蝴蝶结发夹、两侧深蓝垂耳状发片、白衬衫深蓝领结 + 蓝色菱形宝石；深蓝粗描边（约 `#1a1573` / `#1f2a6b`）、浅蓝高光、浅肤色、粉色腮红；Q 版大头。
- **只改脸**：每张图的画布、人物大小、位置、头发、衣服都和 `neutral` 完全一致（同一张底图上改五官 / 加小符号），这样切表情和做下压动画时人物不会跳。
- **源文件**：PNG，**825×1024**（和 `idle.jpg` 同尺寸同构图），**纯白背景 `#FFFFFF`**（不要透明、不要 JPEG 噪点——烟花只画在近白背景上，背景脏了烟花会穿到人物前面）。不要画思考小圆点。

- **禁区**：小符号（!、z、汗滴、星星）不能画进顶部 58 px 的气泡 / 卡片区，也不能画进右下角蛋糕区（屏幕 x 92–122、y 138–153）。

- **转换**：沿用 `portrait_bytes()` 的流程（contain 到 128×160 → 下移 10 px → 旋转 180° → 大端 RGB565），去掉「擦小圆点」那一步（新图本来就没有）。
- **出图方式**：可以用 AI 生图以 `idle.jpg` 为参考出底稿，再手工修成同一底图；也可以找人画。无论哪种，最后都要统一到同一张身体底图。
- **审图步骤（必须）**：
  1. 先出第一批 8 个（★）的 825×1024 PNG；
  2. 用新工具生成审图拼图 `docs/v1.0-expressions-preview.png`：每个表情一格，按真实 128×160 缩小后再放大 2 倍显示（像 `context-preview.png` 那样），下面标表情名和触发场景，最好再配一格带气泡的样子；
  3. 发给 Tim，**Tim 明确说可以之后**才画第二批和眨眼帧；Tim 要改的先改完再继续。

### 2.4 分区和资源包

#### 新分区表（**提议**）

```
# Name,     Type, SubType, Offset,   Size
nvs,        data, nvs,     0x9000,   0x6000
phy_init,   data, phy,     0xf000,   0x1000
factory,    app,  factory, 0x10000,  0x180000
assets,     data, 0x40,    0x190000, 0x200000
```

- `nvs` / `phy_init` / `factory` **偏移和大小一律不动**，这样升级后 NVS 里的 Wi-Fi、密钥、生日、句子池都保留，只需重写分区表（0x8000）。
- `assets`：自定义数据子类型 `0x40`，2 MB；0x390000–0x400000（448 KB）留空备用。
- 固件用 `esp_partition_find_first(ESP_PARTITION_TYPE_DATA, 0x40, "assets")` 找分区。

#### 资源包格式 `assets.bin`（**提议**，小端）

```
偏移  大小  字段
0     4     magic = "DFYA"
4     2     format_version = 1
6     2     header_size = 32
8     4     pack_version（美术版本，如 20261115）
12    2     width = 128
14    2     height = 160
16    1     pixel_format = 1（大端 RGB565，已旋转 180°，和 idle.rgb565 相同）
17    1     flags = 0
18    2     entry_count
20    4     data_size（目录 + 像素数据总字节数）
24    4     data_crc32（header 之后 data_size 字节的 CRC32）
28    4     header_crc32（前 28 字节的 CRC32）

目录：entry_count 项，每项 16 字节
0     1     expr_id（2.1 表）
1     1     variant（0 = base，1 = blink，2 = blow）
2     2     reserved = 0
4     4     offset（从分区起点算，4 字节对齐）
8     4     size（必须 = 128*160*2 = 40960）
12    4     crc32（这张图像素的 CRC32）
```

- CRC32 用和句子池一样的实现（`esp_rom_crc32_le` 或现有函数），工具和固件必须一致。
- 读法：开机 `esp_partition_mmap()` 映射整个包（只读、不占 RAM），校验 header CRC、尺寸、格式，再逐项校验每张图的 CRC，结果记成「可用表情位图」。`paint_portrait()` 改成从一个 `const uint8_t *portrait` 指针取像素（经典版 = 内置 `idle_rgb565_start`，表情版 = 包里对应那张）。**不要再开第二块 40 KB 帧缓冲**（没有 PSRAM）。
- 如果 mmap 地址空间不够，退路是 `esp_partition_read()` 按行读进一个 256 B 行缓冲。

#### 回落规则（必须）

| 情况 | 行为 |
|---|---|
| 没有 `assets` 分区 / magic 不对 / 全是 0xFF（没刷过） | 表情版不可用：照常用内置立绘，网页开关旁显示「表情包未安装，暂用经典立绘」，串口 `ASSETS: missing` |
| header CRC 错、尺寸或格式不对、format_version 不认识 | 整包作废，同上，`ASSETS: bad header` |
| 某张图 CRC 错 | 只丢这一张；该表情回落到 `neutral`，`neutral` 坏了回落到内置立绘，`ASSETS: N bad entries` |
| 任何情况 | **不能死机、不能开机循环**，经典版完全不受影响 |

#### 刷资源包

新工具 `tools/gen_expressions.py`：读 `assets/expressions/<name>.png`、`<name>_blink.png`、`<name>_blow.png`，检查尺寸 825×1024 和白背景，按 2.3 转换，输出 `build/assets.bin`、`docs/v1.0-expressions-preview.png`，打印每张的 CRC。

```sh
# 0. 备份（每次刷机前）
python3 -m esptool --chip esp32c3 --port /dev/cu.usbmodem1101 read-flash 0x0 0x400000 backup-$(date +%Y%m%d-%H%M).bin
# 1. 新分区表（只第一次，从 v0.5 升级时）
python3 -m esptool --chip esp32c3 --port /dev/cu.usbmodem1101 write-flash 0x8000 build/partition_table/partition-table.bin
# 2. 应用
python3 -m esptool --chip esp32c3 --port /dev/cu.usbmodem1101 write-flash --flash-mode dio --flash-size 4MB --flash-freq 40m 0x10000 build/companion.bin
# 3. 资源包（以后只换图时只做这一步，不用重编固件）
python3 -m esptool --chip esp32c3 --port /dev/cu.usbmodem1101 write-flash 0x190000 build/assets.bin
```

也可以 `parttool.py --port … write_partition --partition-name assets --input build/assets.bin`。`main/CMakeLists.txt` 可以加 `esptool_py_flash_to_partition(flash "assets" …)` 方便开发，但 README 里给 Tim 的仍然是上面的分步 esptool 命令。网页上传资源包**不在 v1.0 范围**（问 Tim，第 8 节）。

### 2.5 DeepSeek 返回心情标签（**提议**）

### 2.7 表情版里的动画（**提议**）

- **下压回弹**：同一张 10 帧缩放表、同样的时长和帧率（约 30 帧/秒），只是缩放的是**当前表情图**；气泡照旧不动。叫醒（`sleeping` → `surprised`）在第 1 帧切图。
- **动画后切表情**：回弹结束、气泡出现的同一帧切到句子的心情；7 秒后回到空闲表情。
- **眨眼**：空闲时每 3–6 秒随机眨一次：换 `blink` 帧 120 ms 再换回。只重画脸部矩形（用 ST7735 窗口局部刷新），不要整屏重画，免得闪；有气泡、生日特效、余额时不眨眼。
- **打盹**：`sleeping` 时可以每 2 秒在头旁边画一个程序绘制的小「z」上浮（不画进气泡区）。
- 所有动画仍在 UI 任务里逐帧画，**不能拖慢挥手检测、网页和联网**；单帧不超过 40 ms。
- 经典版：一个像素都不变（和 v0.5 一致），包括没有眨眼。

### 2.8 生日模式（两个版本都要正常）

- 经典版：和 v0.5 完全一样。
- 表情版：同样的气泡、蛋糕、蜡烛、烟花、吹蜡烛、10 句祝福、60 秒重新点蜡烛、自动切换和第二天切回；只是人物用 `excited` / `happy`，吹蜡烛时用 `blow`。烟花依然只画在白背景上（所以新图背景必须纯白）。
